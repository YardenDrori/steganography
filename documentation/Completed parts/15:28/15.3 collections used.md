### 15.3 מבנה נתונים

| מבנה נתונים | תיאור | סיבת השימוש בפרויקט |
|-------------|-------|----------------------|
| מערך בגודל קבוע | אוסף ערכים הומוגני שגודלו ידוע בזמן קומפילציה, מוקצה על ה-stack | שימוש עיקרי בבלוקי פיקסלים ומקדמי DCT - תמיד 16 איברים בדיוק. אין עלות הקצאת heap, גישה בזמן O(1) לפי אינדקס |
| מערך דינמי | אוסף ערכים הומוגני שגדל ומתכווץ בזמן ריצה, מוקצה על ה-heap | הנפוץ ביותר בפרויקט. משמש לכל מקום שגודל הנתונים אינו ידוע מראש: בתי מטען, מקדמי פולינומים ב-RS, ווקטורי יחידה, תוצאות שאילתות DB |
| טבלת גיבוב (Hash Map) | מיפוי מפתח לערך עם גישה ממוצעת O(1) | שימוש במנגנון הצבירה של ההטמעה: מזהה בלוק ממופה לנתוני הבלוק הממתין. חיוני כי בלוקים מגיעים בסדר פריים ולא בסדר הביטים הנדרש |
| מחסנית קריאה מאוחסנת (Buffered Reader) | עוטף מקור קריאה ומאחסן נתח נתונים מראש בזיכרון | קריאת קובץ מטען וקובץ וידאו. ללא buffering, כל גישה לבית בודד היתה גוררת קריאת syscall נפרדת - עלות אדירה על קבצים גדולים |
| טבלאות חיפוש | מערכים סטטיים שמחושבים פעם אחת ומשמשים לחיפוש מהיר | טבלאות EXP ו-LOG של GF(2⁸) לחשבון Reed-Solomon. החלופה היא חישוב לוגריתם/חזקה בכל פעולה - טבלת חיפוש מוזילה את זה לגישת מערך בודדת |
| מבנה (Struct) | קיבוץ שדות קשורים תחת שם אחד | ניהול מצב ההטמעה והחילוץ, ייצוג בלוקים ממתינים, ייצוג בקשות ותשובות API, ישויות מסד נתונים |
| טאפל | קיבוץ ערכים ללא שם מבנה מפורש | ייצוג זוגות ערכים פשוטים שאינם מצדיקים struct מלא, למשל (מזהה בלוק, אינדקס מקדם) בתור הצבירה |
| מחרוזת (String) | רצף תווים בקידוד UTF-8 | שמות קבצים, שגיאות, seed לווקטור היחידה, מפתחות JWT |
| Option | סוג המייצג ערך שעשוי להיות נוכח או נעדר | כל שדה אופציונלי בבקשות API (טלפון, מידע מכשיר), תוצאות חיפוש ב-DB שעשויות להחזיר שורה או כלום |
| Result | סוג המייצג הצלחה עם ערך או כישלון עם שגיאה | כל פונקציה שעלולה להיכשל. מאלץ טיפול מפורש בשגיאות ומונע התעלמות שקטה מכשלים |
| מצביע חכם עם ספירת הפניות (Arc) | מאפשר בעלות משותפת על ערך בין threads שונים | תצורת Eureka חייבת להיות נגישה ממספר threads במקביל (handler threads + background refresh task) |
| נעילת קריאה-כתיבה (RwLock) | מאפשר קוראים מרובים במקביל, כותב יחיד בכל פעם | עוטף את תצורת Eureka בשילוב עם Arc. רוב הגישות הן קריאה בלבד ולכן לא נדרש mutex רגיל שחוסם גם קוראים |
| מאגר חיבורים (Connection Pool) | קבוצת חיבורי DB פתוחים מראש שמשותפים בין בקשות | פתיחת חיבור לכל בקשה יקרה. Pool מחזיק חיבורים פתוחים ומשאיל אותם לבקשות - מפחית latency ומגביל עומס על ה-DB |
| אתחול עצלן (Lazy Initialization) | ערך מחושב רק בגישה הראשונה, ואז שמור | טבלאות GF(2⁸) כבדות לחישוב ולא רצוי לחשבן בזמן עלייה. אתחול עצלן מבטיח שהן נבנות פעם אחת בלבד בפעם הראשונה שנדרשות |
