## 15.9 תרשימי UML — Sequence Diagrams

בחלק זה מוצגים תרשימי רצף עבור ששת הזרימות הלא-טריוויאליות במערכת. כל תרשים מציג את זרימת המידע בין הרכיבים השונים, כולל קריאות בין-שירותיות, פעולות בסיסי הנתונים, ונקודות כשל.

---

### 15.9.1 התחברות (Login)

בזרימת ההתחברות, אימות הסיסמה מתבצע בשירות המשתמשים בעזרת Argon2, ואחר כך שירות ה-Auth מייצר JWT ו-Refresh Token. הטוקן עצמו נשמר בבסיס הנתונים רק כ-hash (SHA256) ומועבר ללקוח כ-HttpOnly cookie.

```mermaid
sequenceDiagram
    participant C as Client
    participant GW as API Gateway
    participant Auth as auth_service
    participant User as user_service
    participant AuthDB as Auth DB
    participant UserDB as User DB

    C->>GW: POST /api/auth/login {email, password}
    GW->>Auth: POST /auth/login (transparent proxy)
    Auth->>User: POST /internal/auth/verify-credentials {email, password}
    User->>UserDB: SELECT * FROM users WHERE email=$1
    UserDB-->>User: user row
    User->>User: Argon2::verify(password, stored_hash)
    User-->>Auth: UserResponse {id, profile}
    Auth->>AuthDB: SELECT role FROM user_roles WHERE user_id=$1
    AuthDB-->>Auth: [Role::User]
    Auth->>Auth: encode_jwt(user_id, roles) — RS256
    Auth->>Auth: generate random 64-char refresh token
    Auth->>Auth: SHA256(token) → token_hash
    Auth->>AuthDB: INSERT INTO refresh_tokens (user_id, token_hash, expires_at, device_info)
    Auth-->>GW: 200 {user, access_token} + Set-Cookie: refresh_token=<plaintext> HttpOnly
    GW-->>C: 200 LoginResponse + Set-Cookie
```

### 15.9.2 הרשמה עם saga compensation (Register)

הרשמה מיישמת דפוס saga: יצירת המשתמש ב-user_service ושיוך התפקיד ב-Auth DB הן שתי פעולות עצמאיות על שני בסיסי נתונים נפרדים. אם שיוך התפקיד נכשל, מתבצע ניסיון מחיקה מפצה ב-user_service עד שלוש פעמים. אם כל הניסיונות נכשלים, הפרופיל נשאר ב-user_service ללא תפקיד — מצב המונע כניסה עתידית.

```mermaid
sequenceDiagram
    participant C as Client
    participant GW as API Gateway
    participant Auth as auth_service
    participant User as user_service
    participant AuthDB as Auth DB
    participant UserDB as User DB

    C->>GW: POST /api/auth/register {username, email, password, ...}
    GW->>Auth: POST /auth/register (proxy)
    Auth->>Auth: validate input (length, email format, username chars)
    Auth->>Auth: Argon2::hash_password(password, OsRng salt)

    Auth->>User: POST /users {username, email, password_hash, ...}
    User->>UserDB: INSERT INTO users (...) RETURNING id
    UserDB-->>User: new user row
    User-->>Auth: UserResponse {id}

    Auth->>AuthDB: INSERT INTO user_roles (user_id, Role::User)
    alt Role insert fails (DB error)
        loop up to 3 compensation attempts
            Auth->>User: DELETE /users/{user_id}
            User->>UserDB: DELETE FROM users WHERE id=$1
        end
        Auth-->>GW: 500 Internal Server Error
        GW-->>C: 500 error
    else Role insert succeeds
        Auth->>AuthDB: SELECT role FROM user_roles WHERE user_id=$1
        Auth->>Auth: encode_jwt(user_id, roles) — RS256
        Auth->>Auth: generate refresh token, SHA256 hash
        Auth->>AuthDB: INSERT INTO refresh_tokens (user_id, token_hash, expires_at)
        Auth-->>GW: 201 {user, access_token} + Set-Cookie: refresh_token HttpOnly
        GW-->>C: 201 LoginResponse + Set-Cookie
    end
```

### 15.9.3 העלאת קובץ (File Upload — S3 Multipart)

העלאת קובץ מתבצעת בשלושה שלבים נפרדים לפי פרוטוקול S3 Multipart. בשלב ה-Complete, המערכת מורידה את 2 ה-MB הראשונים מ-MinIO ומגלה את הקודק בעזרת ffmpeg כדי לסמן האם הקובץ מתאים לשמש carrier לסטגנוגרפיה.

```mermaid
sequenceDiagram
    participant C as Client
    participant GW as API Gateway
    participant Files as files_service
    participant MinIO as MinIO (S3)
    participant FilesDB as Files DB

    Note over C,FilesDB: Step A — Initiate
    C->>GW: POST /api/files/initiate
    GW->>Files: POST /files/initiate (proxy)
    Files->>Files: verify JWT (RSA public key from Eureka)
    Files->>Files: generate UUID → object_key
    Files->>MinIO: initiate_multipart_upload(object_key)
    MinIO-->>Files: upload_id
    Files-->>C: 201 {upload_id, object_key}

    Note over C,FilesDB: Step B — Upload Chunks (repeated per chunk)
    loop for each chunk (max 20 MiB per request)
        C->>GW: POST /api/files/upload-chunk?part_number=N&upload_id=X&object_key=Y
        GW->>Files: POST /files/upload-chunk (proxy)
        Files->>Files: verify JWT
        Files->>MinIO: put_multipart_chunk(bytes, part_number, upload_id)
        MinIO-->>Files: ETag
        Files-->>C: 200 {etag, part_number}
    end

    Note over C,FilesDB: Step C — Complete
    C->>GW: POST /api/files/complete {upload_id, object_key, filename, parts[]}
    GW->>Files: POST /files/complete (proxy)
    Files->>Files: verify JWT
    Files->>MinIO: complete_multipart_upload(object_key, upload_id, parts)
    Files->>MinIO: GET first 2 MB (range request 0..2_000_000)
    MinIO-->>Files: first 2 MB bytes
    Files->>Files: write to tempfile
    Files->>Files: ffmpeg probe codec ID
    Files->>Files: is codec in [H264, HEVC, VP9, VP8, AV1, MPEG4]? → is_carrier
    Files->>FilesDB: INSERT INTO files (user_id, filename, object_key, is_carrier, is_steg_object=false)
    FilesDB-->>Files: FileResponse
    Files-->>C: 201 FileResponse {id, filename, is_carrier, ...}
```

### 15.9.4 הטמעת מידע (Embed Pipeline)

זרימת ה-Embed מורידה את שני הקבצים במקביל בעזרת `tokio::try_join!`, מריצה את אלגוריתם ה-DCT בthread נפרד (spawn_blocking) כדי לא לחסום את ה-async runtime, ומעלה את הפלט ל-files_service בפרוטוקול ה-S3. בסיום, קריאת PATCH פנימית מסמנת את הקובץ כ-steg object. לפני ההטמעה, ה-payload עובר הצפנת AES-256 ואחר כך קידוד Reed-Solomon להוספת יתירות לתיקון שגיאות (TODO).

```mermaid
sequenceDiagram
    participant C as Client
    participant GW as API Gateway
    participant Steg as steganography_service
    participant Files as files_service
    participant MinIO as MinIO (S3)

    C->>GW: POST /api/embed {carrier_id, payload_id, configs}
    GW->>Steg: POST /embed (proxy)
    Steg->>Steg: verify JWT → (user_id, access_token)

    par Download carrier (tokio::try_join!)
        Steg->>Files: GET /files/{carrier_id} (with user token)
        Files-->>Steg: FileResponse {is_carrier, filename}
        Steg->>Files: GET /files/{carrier_id}/download
        Files->>MinIO: stream object
        MinIO-->>Files: object bytes
        Files-->>Steg: streamed bytes → tempfile
    and Download payload
        Steg->>Files: GET /files/{payload_id}
        Files-->>Steg: FileResponse {filename}
        Steg->>Files: GET /files/{payload_id}/download
        Files->>MinIO: stream object
        MinIO-->>Files: object bytes
        Files-->>Steg: streamed bytes → tempfile
    end

    Steg->>Steg: verify carrier.is_carrier == true

    Note over Steg: spawn_blocking — CPU-bound encoding
    activate Steg
    Steg->>Steg: validate configs (coeff selection, delta, method)
    Steg->>Steg: [TODO] AES-256 encrypt payload bytes → ciphertext
    Steg->>Steg: [TODO] Reed-Solomon encode ciphertext → RS blocks (adds redundancy)
    Steg->>Steg: open carrier via ffmpeg decoder + create encoder (same codec, crf=23)
    Steg->>Steg: prepend 8-byte LE size header to encoded payload
    loop for each I-frame
        Steg->>Steg: DCT on 4x4 blocks across Y/Cb/Cr planes
        Steg->>Steg: embed bits via QIM / SS / ISS / STDM
        Steg->>Steg: IDCT → write modified frame to encoder
    end
    alt payload_exhausted == false
        Steg->>Steg: discard output file
        Steg-->>GW: 400 InsufficientCapacity
        GW-->>C: 400 error
    else payload_exhausted == true
        Steg->>Steg: write_trailer() → output file ready
    end
    deactivate Steg

    Steg->>Files: POST /files/initiate (user token)
    Files-->>Steg: {upload_id, object_key}
    loop 5 MiB chunks of steg output
        Steg->>Files: POST /files/upload-chunk
        Files->>MinIO: put_multipart_chunk
        Files-->>Steg: {etag, part_number}
    end
    Steg->>Files: POST /files/complete {filename: "payload → carrier"}
    Files-->>Steg: FileResponse {id}
    Steg->>Files: PATCH /internal/files/{id}/embedded (mark is_steg_object=true)
    Files-->>Steg: 200 OK

    Steg-->>GW: 201 FileResponse (steg object)
    GW-->>C: 201 FileResponse
```

### 15.9.5 חילוץ מידע (Extract Pipeline)

זרימת ה-Extract מורידה קובץ steg אחד, מפעילה את אלגוריתם החילוץ בthread נפרד, ומעלה את הפלט. בשונה מה-Embed, לא מתבצעת קריאת PATCH — הקובץ שנחלץ מוחזר כקובץ רגיל. שם הקובץ נגזר מהמקורי: `"payload → carrier"` מפוצל על `" → "` ולחצי הראשון מתווספת הסיומת `"(1)"`. לאחר חילוץ הביטים, מתבצע פענוח Reed-Solomon לתיקון שגיאות ואחר כך פענוח AES-256 לשחזור ה-payload המקורי (TODO).

```mermaid
sequenceDiagram
    participant C as Client
    participant GW as API Gateway
    participant Steg as steganography_service
    participant Files as files_service
    participant MinIO as MinIO (S3)

    C->>GW: POST /api/extract {steg_object_id, configs}
    GW->>Steg: POST /extract (proxy)
    Steg->>Steg: verify JWT → (user_id, access_token)

    Steg->>Files: GET /files/{steg_object_id}
    Files-->>Steg: FileResponse {is_steg_object, filename}
    Steg->>Steg: verify is_steg_object == true
    Steg->>Files: GET /files/{steg_object_id}/download
    Files->>MinIO: stream object
    MinIO-->>Files: object bytes
    Files-->>Steg: streamed bytes → tempfile

    Note over Steg: spawn_blocking — CPU-bound decoding
    activate Steg
    Steg->>Steg: open steg object via ffmpeg (decode-only, no encoder)
    loop for each I-frame
        Steg->>Steg: DCT on 4x4 blocks
        Steg->>Steg: extract bit via QIM / SS / ISS / STDM
        Steg->>Steg: first 64 bits → parse payload_size (u64 little-endian)
        Steg->>Steg: write bits to output tempfile
        Steg->>Steg: stop when extracted >= payload_size
    end
    Steg->>Steg: flush writer → raw extracted bytes
    Steg->>Steg: [TODO] Reed-Solomon decode → correct bit-flip errors → ciphertext
    Steg->>Steg: [TODO] AES-256 decrypt ciphertext → original payload bytes
    Steg->>Steg: output_path ready
    deactivate Steg

    Steg->>Files: POST /files/initiate (user token)
    Files-->>Steg: {upload_id, object_key}
    loop 5 MiB chunks of extracted payload
        Steg->>Files: POST /files/upload-chunk
        Files->>MinIO: put_multipart_chunk
        Files-->>Steg: {etag, part_number}
    end
    Steg->>Files: POST /files/complete {filename: "original_name(1)"}
    Files-->>Steg: FileResponse
    Note over Steg,Files: no PATCH — extracted file is a regular file, not a steg object

    Steg-->>GW: 201 FileResponse (extracted payload)
    GW-->>C: 201 FileResponse
```

### 15.9.6 חידוש טוקן (Token Refresh)

Refresh Token מאוחסן בבסיס הנתונים רק כ-SHA256 hash. בכל קריאת refresh מתבצעת token rotation ללא תלות בשאלה האם הטוקן עדיין בתוקף — הטוקן הישן מבוטל ומוחלף בחדש. פרטי המכשיר (device_info) עוברים לטוקן החדש.

```mermaid
sequenceDiagram
    participant C as Client
    participant GW as API Gateway
    participant Auth as auth_service
    participant AuthDB as Auth DB

    C->>GW: POST /api/auth/refresh (Cookie: refresh_token=plaintext)
    GW->>Auth: POST /auth/refresh (proxy)
    Auth->>Auth: extract refresh_token from Cookie header
    Auth->>Auth: SHA256(token) → token_hash
    Auth->>AuthDB: SELECT * FROM refresh_tokens WHERE token_hash=$1
    AuthDB-->>Auth: result

    alt token not found
        Auth-->>GW: 401 Unauthorized
        GW-->>C: 401 Unauthorized
    else token found but expires_at < now()
        Auth->>AuthDB: DELETE FROM refresh_tokens WHERE id=$1
        Auth-->>GW: 401 Unauthorized
        GW-->>C: 401 Unauthorized
    else token found and valid
        Auth->>AuthDB: DELETE FROM refresh_tokens WHERE id=$1 (rotation)
        Auth->>AuthDB: SELECT role FROM user_roles WHERE user_id=$1
        AuthDB-->>Auth: roles[]
        Auth->>Auth: encode_jwt(user_id, roles) — RS256
        Auth->>Auth: generate new 64-char refresh token
        Auth->>Auth: SHA256(new_token) → new_hash
        Auth->>AuthDB: INSERT INTO refresh_tokens (user_id, new_hash, expires_at, device_info)
        Auth-->>GW: 200 access_token + Set-Cookie: refresh_token=new_plaintext HttpOnly
        GW-->>C: 200 RefreshTokenResponse + Set-Cookie
    end
```
