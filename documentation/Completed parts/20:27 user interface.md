# תיעוד פרויקט - פלטפורמת סטגנוגרפיה בווידאו

---

## 20 — ממשק המשתמש

### 20.1 סקירה כללית

ממשק המשתמש נבנה כ-Single Page Application — האפליקציה נטענת פעם אחת ומנהלת את כל הניווט בצד הלקוח ללא טעינות דף מחדש. הוא פועל מול ה-API Gateway שמשמש כנקודת כניסה יחידה לכלל הבקשות.

הממשק בנוי בשלוש שכבות:

| שכבה | תפקיד |
|---|---|
| שכבת התצוגה | רכיבי React המרנדרים את ממשק המשתמש |
| שכבת המצב | AuthContext המנהל את מצב האימות הגלובלי |
| שכבת ה-API | פונקציות axios המתקשרות עם ה-Gateway |

---

### 20.2 טכנולוגיות הממשק

**React 19** — ספריית JavaScript לבניית ממשקי משתמש מבוססי רכיבים. כל מסך ואלמנט מיושם כרכיב עצמאי עם מצב פנימי משלו.

**TypeScript** — סופר-סט של JavaScript המוסיף בדיקת טיפוסים בזמן קומפילציה. כל ממשקי הנתונים המתקבלים מהשרת מוגדרים כטיפוסים מפורשים, מה שמונע חלק גדול מהבאגים עוד לפני ריצה.

**Vite** — כלי build המשמש לאריזת הקוד לפריסה ולהרצת שרת פיתוח עם hot module replacement — עדכון מיידי של הדפדפן עם כל שינוי בקוד.

**Tailwind CSS v4** — framework לעיצוב המאפשר הגדרת סגנון ישירות בתוך ה-JSX באמצעות class names. מבטיח עקביות ויזואלית ומבטל קבצי CSS נפרדים לרוב הרכיבים.

**React Router** — ספרייה לניהול ניווט בצד הלקוח. מגדירה את מבנה הנתיבים ואת מנגנון ה-ProtectedRoute.

**axios** — ספריית HTTP לתקשורת עם השרת, עם תמיכה ב-interceptors המאפשרים טיפול גלובלי בשגיאות ורענון טוקן אוטומטי.

### 20.4 ניהול מצב האימות

מצב האימות מנוהל דרך `AuthContext` — Context גלובלי הנגיש לכל רכיב באפליקציה. הוא מכיל שלושה ערכים:

| ערך | סוג | תפקיד |
|---|---|---|
| `accessToken` | string או null | הטוקן הנוכחי לשליחה בכותרות הבקשות |
| `user` | User או null | פרטי המשתמש המחובר |
| `isLoading` | boolean | האם שחזור הסשן הראשוני עדיין בתהליך |

בעת טעינת האפליקציה, `App.tsx` מבצע ניסיון שחזור סשן: הוא שולח בקשת רענון לשרת תוך שימוש ב-refresh token השמור בעוגייה. אם הבקשה מצליחה — מאוחסנים access token חדש ופרטי המשתמש ב-Context. אם נכשלת — `isLoading` מוגדר ל-false והמשתמש נשאר מנותק. כל מסך מוגן ממתין לסיום הבדיקה הזו לפני שמחליט אם להציג את התוכן או לפנות למסך ההתחברות.

---

### 20.5 מנגנון רענון הטוקן האוטומטי

`authInterceptor.ts` מגדיר interceptor על כל בקשות axios היוצאות מהאפליקציה. כאשר שרת מחזיר שגיאת 401 (Unauthorized), ה-interceptor:

1. שולח בקשת רענון לשרת תוך שימוש ב-refresh token שבעוגייה.
2. ממתין לתגובה, ובהצלחה מעדכן את ה-access token ב-Context.
3. שולח מחדש את הבקשה המקורית שנכשלה — עם הטוקן החדש.
4. אם הרענון נכשל גם הוא — מנקה את מצב האימות ומחזיר את המשתמש למסך ההתחברות.

מנגנון זה שקוף לחלוטין לשאר הקוד — רכיבי ה-UI אינם מודעים לתהליך הרענון ואינם צריכים לטפל בו ידנית. בנוסף, בקשות מקבילות מרובות שנכשלות ב-401 בו-זמנית כולן ממתינות לאותה בקשת רענון יחידה, ולא שולחות בקשות רענון מרובות.

---

### 20.6 מבנה הפריסה

כל מסך מוגן עטוף ברכיב `Layout` המספק את המבנה הבסיסי של הדף. הפריסה מחולקת לשתי עמודות:

**עמודה שמאלית — סרגל ניווט צדי:** ברוחב קבוע, מכיל את לוגו המוצר, קישורי הניווט, פרטי המשתמש וכפתור ההתנתקות. הסרגל גלוי בכל עת ואינו נגלל עם תוכן הדף.

**עמודה ימנית — אזור התוכן:** תופסת את שאר רוחב המסך ומציגה את תוכן המסך הפעיל. גולל בנפרד מהסרגל הצדי.

מסכי ההתחברות והרשמה אינם עטופים ב-Layout ומציגים תוכן ממורכז בלבד ללא סרגל ניווט.

---

### 20.7 ניהול הניווט

הניווט מנוהל על ידי React Router בצד הלקוח. קיימים שני סוגי נתיבים:

**נתיבים ציבוריים** — `/login` ו-`/register` — נגישים ללא אימות.

**נתיבים מוגנים** — `/`, `/my-files`, `/embed`, `/extract`, `/settings` — עטופים ברכיב `ProtectedRoute`. הרכיב בודק את מצב ה-Context: אם `isLoading` — מחכה בשקט; אם המשתמש null — מפנה ל-`/login`; אחרת — מרנדר את התוכן בתוך `Layout`.

ניווט בין מסכים מתבצע דרך React Router ללא טעינת דף. העברת מידע בין מסכים (כגון העברת carrier שנבחר ממסך הקבצים למסך ההטמעה) מתבצעת דרך `location.state` של React Router.

נתיב `/my-files/embed` נותר קיים לצורך תאימות לאחור ומפנה אוטומטית ל-`/embed`.
