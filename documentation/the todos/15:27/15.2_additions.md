### תוספות ל-15.2 — Use Cases מתוכננים

---

#### UC-19: אימות מייל (מתוכנן)

| שדה | ערך |
|-----|-----|
| **תיאור** | לאחר הרשמה, המשתמש מקבל מייל עם קישור אימות. לחיצה על הקישור מאמתת את כתובת המייל ומסמנת את החשבון כמאומת |
| **שחקנים** | משתמש לא מאומת |
| **תנאי קדם** | המשתמש נרשם למערכת; שדה `is_verified` מוגדר כ-`false` |
| **תנאי יציאה** | שדה `is_verified` עודכן ל-`true` בטבלת המשתמשים |

**זרימה ראשית:**
1. בסיום ההרשמה, שירות האימות מייצר טוקן אימות ייחודי ושומר אותו עם תאריך תפוגה.
2. המערכת שולחת מייל עם קישור המכיל את הטוקן.
3. המשתמש לוחץ על הקישור; הלקוח שולח את הטוקן ל-`POST /auth/verify-email`.
4. שירות האימות מאמת את הטוקן, מוחק אותו ומעדכן `is_verified = true` דרך שירות המשתמשים.

**זרימות חלופיות:**
- אם הטוקן פג תוקף — 400 Bad Request; המשתמש יכול לבקש שליחה מחדש.
- אם הטוקן לא קיים — 400 Bad Request.

#### UC-20: צפייה בסשנים פעילים (מתוכנן)

| שדה | ערך |
|-----|-----|
| **תיאור** | משתמש מציג את רשימת כל המכשירים שמהם הוא מחובר כעת — כל רשומת refresh token פעילה שמשויכת לחשבונו, כולל `device_info` ותאריך יצירה |
| **שחקנים** | משתמש מזוהה |
| **תנאי קדם** | המשתמש מחובר ויש לו לפחות refresh token אחד פעיל |
| **תנאי יציאה** | רשימת הסשנים הפעילים הוחזרה ללקוח |

**זרימה ראשית:**
1. הלקוח שולח בקשה ל-`GET /auth/sessions` עם access token.
2. שירות האימות שולף מטבלת `refresh_tokens` את כל הרשומות לפי `user_id` שטרם פגו.
3. מוחזרת רשימה של רשומות, כל אחת עם: `id`, `device_info`, `created_at`, `expires_at`.

**הערה:** ה-`id` של כל רשומה ישמש כמזהה הסשן ב-UC-21.

#### UC-21: ביטול סשן ספציפי (מתוכנן)

| שדה | ערך |
|-----|-----|
| **תיאור** | משתמש מנתק מכשיר ספציפי מרחוק על ידי ביטול ה-refresh token המשויך אליו, מבלי להשפיע על שאר הסשנים הפעילים |
| **שחקנים** | משתמש מזוהה |
| **תנאי קדם** | הסשן המבוקש קיים בטבלת `refresh_tokens` ושייך למשתמש המבקש |
| **תנאי יציאה** | רשומת ה-refresh token נמחקת; המכשיר שנותק לא יוכל לרענן טוקנים |

**זרימה ראשית:**
1. הלקוח שולח בקשה ל-`DELETE /auth/sessions/:session_id` עם access token.
2. שירות האימות מאמת שהרשומה ב-`refresh_tokens` עם המזהה הנתון שייכת ל-`user_id` של המשתמש המבקש.
3. הרשומה נמחקת.

**זרימות חלופיות:**
- אם הסשן לא קיים — 404 Not Found.
- אם הסשן שייך למשתמש אחר — 403 Forbidden.

**הערה:** access token שכבר הונפק למכשיר שנותק יישאר תקין עד לפקיעתו הטבעית (בדרך כלל 15 דקות). ביטול מיידי דורש blacklist, שאינו מיושם.

#### UC-23: צפייה בסשנים פעילים של משתמש (מנהל, מתוכנן)

| שדה | ערך |
|-----|-----|
| **תיאור** | מנהל מציג את כל הסשנים הפעילים של משתמש ספציפי — כל ה-refresh tokens הפעילים עם `device_info`, כדי לאבחן חשבונות חשודים או לנתק מכשירים לא מורשים |
| **שחקנים** | מנהל מערכת |
| **תנאי קדם** | המשתמש המבוקש קיים |
| **תנאי יציאה** | רשימת הסשנים הפעילים של המשתמש הוחזרה למנהל |

**זרימה ראשית:**
1. המנהל שולח בקשה ל-`GET /admin/users/:id/sessions`.
2. שירות האימות שולף מטבלת `refresh_tokens` את כל הרשומות לפי `user_id` שטרם פגו.
3. מוחזרת רשימה של רשומות עם: `id`, `device_info`, `created_at`, `expires_at`.

**זרימות חלופיות:**
- אם המשתמש לא קיים — 404 Not Found.
- אם למשתמש אין סשנים פעילים — מוחזרת רשימה ריקה.
